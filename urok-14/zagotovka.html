Частина 1. Вісім селекторів

ЗА ІМЕНЕМ
 
p { }              усім абзацам на сторінці
.card { }          тим, кому дали class="card"
#contacts { }      одному блоку з id="contacts"
h1, h2, h3 { }     трьом тегам одразу, через кому
 
ЗА МІСЦЕМ І АТРИБУТОМ
 
nav a { }          посиланням УСЕРЕДИНІ nav,
                   на будь-якій глибині
nav > a { }        тільки прямим дітям nav
h1 + p { }         абзацу одразу після h1
a[target] { }      посиланням, у яких є target
  • Тег — для спільних правил: колір тексту, тло сторінки.
  • Клас — основний інструмент. Дев'яносто відсотків часу ви користуєтесь саме ним.
  • id — один на всю сторінку. Для стилів майже не беруть; справжнє застосування буде на уроці 17.
  • Кома — економить рядки: замість трьох однакових правил одне.
  • Вкладений — звертаємось за місцем, а не за ім'ям. Пробіл означає «усередині».
  • Дочірній > — тільки прямі діти: абзац, захований ще в один блок, не зачепить.
  • Сусідній + — елемент, що стоїть одразу після іншого, на тому ж рівні.
  • Атрибут у квадратних дужках: [title] — у кого він є, [type="email"] — у кого саме таке значення. Пишеться впритул до тега.

Пробіл вирішує все

.card.large { }    один елемент,
                   у якого обидва класи
 
.card .large { }   елемент large УСЕРЕДИНІ
                   елемента card
 
a[target] { }      посилання з атрибутом
a [target] { }     щось з атрибутом УСЕРЕДИНІ
                   посилання

Виглядають майже однаково, а це різні правила. Помилки не видно: браузер мовчить, правило просто не діє.

Не застосувалось — перевіряйте пробіли першими.

Крапка і ґратка

У HTML                    У CSS
 
class="card"              .card { }
id="contacts"             #contacts { }

У HTML імені ні крапки, ні ґратки немає. У CSS клас — із крапкою, id — із ґраткою. Плутають це всі й постійно.

Як називати класи

ТАК НЕ ТРЕБА      А ТАК ТРЕБА
 
.block1           .notice
.block2           .product-name
.block3           .card

Що таке block2, через тиждень не згадаєте навіть ви. Ім'я має казати, що це за блок.

І не за кольором: клас red збреше, щойно колір зміниться. notice («оголошення») лишиться правдою.

Англійськими словами, маленькими літерами, через дефіс. Не українськими словами латиницею — ваш код читатимуть інші, і так прийнято скрізь.

Кілька класів одному тегу

<p class="card large">

Через пробіл. Застосуються обидва правила.

Частина 2. Вага селекторів

Що буде, якщо на один елемент діють два правила й вони суперечать. Браузер обирає за вагою.

НАЙЛЕГШИЙ
  1  p { }                тег
  2  .card { }  [title]   клас і атрибут — однаково
  3  #contacts { }        id сильніший за клас
  4  style="color: red"   інлайновий переважує все
НАЙВАЖЧИЙ

За однакової ваги перемагає те правило, що нижче у файлі. Коли ваги різні, порядок не має значення.

Ось чому інлайнові стилі не люблять: вони переважують усе, що написано у файлі, і виправити їх із style.css неможливо.

Складені селектори

Порівнюємо по сходинках, згори вниз, до першої різниці: спершу кількість id, потім класів і атрибутів, потім тегів. Порівну всюди — перемагає нижнє.

a              проти  nav a          → nav a
nav ul li a    проти  .menu a        → .menu a
.card .text p  проти  #contacts p    → #contacts p
nav a          проти  nav > a        → нижнє у файлі

Нижча сходинка ніколи не переможе вищу: десять тегів не переважать один клас. Знаки пробіл, > і + нічого не важать.

!important

color: #C8553D !important;

Це не клас, а позначка після значення. Тому наш клас для доставки — notice, а не important: щоб не плутати.

Переважує навіть інлайновий стиль. Але коли знадобиться перебити вже це правило, доведеться писати ще один !important — і так до нескінченності.

Правило просте: побачили !important у своєму коді — значить, зі стилями щось не так. На уроці 21 я перевірятиму, чи його немає.

Частина 3. Приклад

Так це виглядає разом. Наберіть руками й підставте свої кольори.

У HTML:
 
<nav>
  <a href="#">Головна</a>
  <a href="#">Каталог</a>
</nav>
 
<h1>Кава щодня</h1>
<p>Обсмажуємо самі.</p>
 
<p class="notice">
  Доставка безкоштовна від 500 гривень.
</p>
 
 
У CSS:
 
h1, h2, h3 {
  color: #C8553D;
}
 
nav a {
  color: #2B2118;
}
 
h1 + p {
  color: #C8553D;
}
 
.notice {
  background: rgba(200, 85, 61, 0.1);
}

Правило через кому задає колір трьом заголовкам одразу. nav a фарбує тільки посилання в меню. h1 + p — тільки абзац під головним заголовком. Клас notice звертається до одного абзацу.

Коли не працює

Клас не спрацьовує

  • У CSS перед ім'ям має бути крапка: .notice, а не notice.
  • У HTML крапки немає: class="notice".
  • Ім'я має збігатися точно, разом із великими й маленькими літерами.

Написав правило, а колір не той

  • Десь є друге правило з більшою вагою. Порахуйте в обох селекторах id, потім класи й атрибути, потім теги.
  • Якщо ваги однакові — перемагає нижнє. Подивіться, що написано далі у файлі.

Вкладений, дочірній чи сусідній не спрацював

  • Перевірте, чи елемент справді лежить усередині. Відкрийте інспектор і подивіться на дерево.
  • Перевірте пробіл: .card.large і .card .large, a[target] і a [target] — різні правила.
  • h1 + p не спрацював — між ними є ще якийсь тег. Сусід має стояти одразу після.

Застрягли більше ніж на п'ятнадцять хвилин — пишіть у Classroom або на пошту.

Що здати

  • Класи блокам, які треба оформити окремо. Англійськими словами, за змістом.
  • Одне правило через кому — для кількох тегів одразу.
  • Одне правило за місцем: вкладеним (nav a), дочірнім (nav > a) або сусіднім (h1 + p) селектором.
  • Проба: два правила на один елемент, які суперечать. Який переміг і чому — одним реченням.

Перевірятиму: чи імена англійською, чи за змістом — без block1 і без red, чи є селектор за місцем, чи пояснено, хто переміг.

Останній пункт найцінніший. Побачити результат може кожен, назвати причину — ні.

Розмірів і відступів у завданні немає навмисно: розміри наступного уроку.
