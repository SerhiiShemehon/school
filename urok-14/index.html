Урок 14. Усе про селектори

Технічне проектування · Шемегон С. В. · матеріал для самостійного опрацювання

Що ви отримаєте наприкінці

Вісім способів звернутись саме до того блока, що треба, — і розуміння, яке правило переможе, коли їх два.

Розмірів і відступів тут немає: розміри будуть наступного уроку, відступи трохи пізніше. Блоки поки злипатимуться, і це нормально.

Частина 1. Проблема, з якої все починається

Ви хочете пофарбувати один абзац — той, де про безкоштовну доставку. Пишете:

p {
  color: #C8553D;
}

І фарбуються всі абзаци. Браузер зробив рівно те, що ви попросили: селектор p означає «кожен абзац», без винятків.

Потрібен спосіб назвати один конкретний блок.

Частина 2. Класи

У HTML — БЕЗ крапки        У CSS — ІЗ крапкою
 
<p class="notice">          .notice {
  Доставка безкоштовна         color: #C8553D;
</p>                        }

notice англійською — «оголошення», «примітка». Абзац про доставку саме такий.

Перевіряйте це першим, коли клас не спрацьовує: у HTML імені крапка не потрібна, у CSS потрібна.

Дві речі, які варто знати одразу

  • Один клас — багатьом тегам. Позначили п'ять блоків іменем card — правило пишете один раз.
  • Одному тегу — кілька класів, через пробіл: class="card large". Застосуються обидва правила.

Як називати

ТАК НЕ ТРЕБА      А ТАК ТРЕБА
 
.block1           .notice
.block2           .product-name
.block3           .card

Що таке block2? Ніхто не знає — і ви самі через тиждень не згадаєте, доведеться відкривати HTML і шукати. А notice чи card зрозумілі з першого погляду.

Тобто за змістом. Це вже втретє за цей блок: заголовок обирали за змістом, strong замість b — за змістом, і клас так само.

І не за кольором: клас red здається зрозумілим, але через місяць ви вирішите, що оголошення має бути синім, — і red стане брехнею.

Англійськими словами, маленькими літерами, через дефіс. Не українськими словами латиницею: ваш код читатимуть інші, і так прийнято скрізь.

Вправа 1

Дайте абзацу про доставку клас і пофарбуйте тільки його. Переконайтесь, що інші абзаци не змінились.

Частина 3. id

У HTML                    У CSS — ІЗ ҐРАТКОЮ
 
<div id="contacts">       #contacts {
                            color: #C8553D;
                          }

Головна відмінність від класу: id має бути один на всю сторінку. Двох однакових бути не може.

Чесно: для оформлення id майже не беруть. Він надто важкий — чому саме, зрозумієте в частині 7 — і не повторюється, тобто одне правило для п'яти блоків не напишеш.

Справжнє застосування id — якір: адреса всередині сторінки, щоб посилання прокручувало до потрібного місця. Це буде на уроці 17.

Частина 4. Звертаємось за місцем

Досі ми зверталися за іменем. Тепер — за тим, де елемент лежить на сторінці. Жодного класу давати не треба.

Вкладений: пробіл

nav a {
  color: #C8553D;
}

Читається так: «усім посиланням, які лежать усередині nav», на будь-якій глибині.

Навіщо: посилання в меню й посилання всередині тексту майже завжди мають виглядати по-різному.

Рівнів може бути скільки завгодно: .card p span теж спрацює. Але більше двох пишуть рідко — такі правила стають крихкі.

Дочірній: знак >

.card > p { }
 
<div class="card">
  <p>цей — так</p>            пряма дитина card
  <div>
    <p>цей — ні</p>           онук, захований ще в один div
  </div>
</div>

Тільки прямі діти. Із пробілом (.card p) зачепило б обидва абзаци, зі знаком > — тільки перший.

На меню «Горнятка» nav a і nav > a дадуть однаковий результат: посилання лежать у nav напряму. Різниця з'являється, коли є ще один рівень.

Сусідній: знак +

h1 + p { }
 
<h1>Кава щодня</h1>
<p>цей — так</p>              стоїть одразу після h1
<p>цей — ні</p>

Елемент, що стоїть одразу після іншого, на тому ж рівні. Наступні не зачепить.

Навіщо: перший абзац після заголовка часто оформлюють як підзаголовок — і клас для цього не потрібен.

Є ще знак ~ (тильда) — усі наступні сусіди, а не тільки перший. Трапляється рідко.

Вправа 2

  • Пофарбуйте посилання в меню вкладеним селектором так, щоб посилання в тексті лишились іншими.
  • Пофарбуйте селектором h1 + p абзац під головним заголовком. Переконайтесь, що інші абзаци не змінились.

Частина 5. Звертаємось за атрибутом

Атрибути ви знаєте з уроку 11: href, alt, target. До тегів можна звертатись і за ними — у квадратних дужках.

a[target="_blank"] { }     посиланням, що відкриваються
                           в новій вкладці
 
[title] { }                усім, у кого атрибут title є
 
input[type="email"] { }    тільки полю для пошти

Без значення — усім, у кого атрибут є взагалі. Зі значенням у лапках — тільки тим, у кого воно саме таке.

Найбільше це знадобиться у формах, на уроці 20.

Дві речі запам'ятайте: вага в атрибута така сама, як у класу. І дужка пишеться впритул: a[target], а не a [target].

Частина 6. Пробіл вирішує все

.card.large { }    один елемент,
                   у якого обидва класи одразу
 
.card .large { }   елемент large УСЕРЕДИНІ
                   елемента card

Виглядають майже однаково, а це два зовсім різні правила. Так само a[target] — посилання з атрибутом, а a [target] — щось з атрибутом усередині посилання.

І головне: помилки не видно. Браузер мовчить, правило просто не діє, а ви сидите й не розумієте чому.

Правило: не застосувалось — перевіряйте пробіли першими.

Вісім селекторів разом

ЗА ІМЕНЕМ
p { }              усім абзацам
.card { }          тим, кому дали class="card"
#contacts { }      одному блоку з id="contacts"
h1, h2, h3 { }     трьом тегам одразу, через кому
 
ЗА МІСЦЕМ І АТРИБУТОМ
nav a { }          посиланням усередині nav, на будь-якій глибині
nav > a { }        тільки прямим дітям nav
h1 + p { }         абзацу одразу після h1
a[target] { }      посиланням, у яких є target
  • Клас — основний інструмент, 90% часу.
  • Тег — для спільних правил. id — для стилів майже не беруть.
  • Кома — економить рядки: замість трьох однакових правил одне.
  • Пробіл, > і + — коли простіше сказати, де лежить елемент, ніж давати йому клас.

Частина 7. Вага селекторів

Головне питання: що буде, якщо на один елемент діють два правила і вони суперечать?

Браузер не губиться — він обирає за вагою.

НАЙЛЕГШИЙ
  1  p { }                  тег
  2  .card { }  [title] { } клас і атрибут — однаково,
                            обидва сильніші за тег
  3  #contacts { }          id сильніший за клас
  4  style="color: red"     інлайновий переважує все
НАЙВАЖЧИЙ

За однакової ваги перемагає те правило, що нижче у файлі. Коли ваги різні, порядок не має значення взагалі.

Ось і відповідь на питання з минулого уроку, чому інлайнові стилі не люблять: вони переважують усе, що написано у файлі, і виправити їх із style.css неможливо.

Складені селектори: порівнюємо від найважчого

А якщо селектор складений, як nav a чи .card .text p? Порівнюємо по сходинках, згори вниз, і зупиняємось на першій різниці:

  • Спершу рахуємо id. У кого більше — той переміг.
  • Порівну — рахуємо класи й атрибути.
  • Знову порівну — рахуємо теги.
  • Порівну й тут — перемагає нижнє у файлі.
a              проти  nav a          переміг nav a:
                                     класів немає, тегів більше
 
nav ul li a    проти  .menu a        переміг .menu a:
                                     клас важчий за будь-яку
                                     кількість тегів
 
.card .text p  проти  #contacts p    переміг #contacts p:
                                     id важчий за будь-яку
                                     кількість класів
 
nav a          проти  nav > a        перемагає нижнє:
                                     знак > ваги не додає

Головне: нижча сходинка ніколи не переможе вищу, хоч скільки її набрати. Десять тегів не переважать один клас.

Знаки між частинами — пробіл, >, + — нічого не важать. Рахуються тільки самі частини. А правило через кому — це кілька окремих правил, кожне важить само по собі.

!important

color: #C8553D !important;

Це не клас, а позначка в самому правилі, після значення. Саме тому клас для абзацу про доставку називається notice, а не important — щоб не плутати.

Переважує навіть інлайновий стиль. Звучить зручно — насправді пастка: коли знадобиться перебити вже це правило, доведеться писати ще один !important, потім ще один.

Правило: побачили !important у своєму коді — значить, зі стилями щось не так, і варто розібратись із вагою. На уроці 21 я перевірятиму, чи його немає.

Вправа 3

  • Задайте абзацу колір через p, а потім той самий абзац — через клас. Подивіться, який переміг.
  • Поміняйте правила місцями у файлі. Чи щось змінилось? Поясніть чому.
  • Тепер напишіть два правила на той самий клас, із різними кольорами. Який переміг тепер?
  • Напишіть a { } з одним кольором нижче за nav a { } з іншим. Якого кольору меню? Поясніть, порахувавши частини.

П'ять помилок цього уроку

  • Крапка не там. У HTML без крапки, у CSS із крапкою. Перевіряйте це першим.
  • Ім'я без змісту: block1 чи red замість notice.
  • Стилі через id. Працює, але переважує класи, і перебити потім буде важко.
  • Зайвий пробіл у селекторі: .card .large замість .card.large, a [target] замість a[target].
  • !important там, де досить було розібратись із вагою.

Третя й п'ята — одна й та сама проблема з різних боків: людина не розібралась у вазі й б'є молотком.

Перевірте себе

Ви опрацювали тему, якщо можете зробити все це:

  • Пояснити, навіщо потрібні класи, якщо є селектор за тегом.
  • Сказати, де ставиться крапка, а де ґратка.
  • Пояснити, чому клас не називають block2 чи red.
  • Пояснити різницю між nav a, nav > a і h1 + p.
  • Записати селектор для посилань, які відкриваються в новій вкладці.
  • Назвати чотири сходинки ваги від найлегшої до найважчої і сказати, де стоїть атрибут.
  • Сказати, хто переможе: nav ul li a чи .menu a, — і чому.
  • Пояснити різницю між .card.large і .card .large.

Що здати

У Classroom до наступного уроку: файли або скріншот.

  • Класи блокам, які треба оформити окремо. Англійськими словами, за змістом.
  • Одне правило через кому — для кількох тегів одразу.
  • Одне правило за місцем: вкладеним (nav a), дочірнім (nav > a) або сусіднім (h1 + p) селектором.
  • Проба: два правила на один елемент, які суперечать. Який переміг і чому — одним реченням.

Перевірятиму: чи імена англійською, чи за змістом — без block1 і без red, чи є селектор за місцем, чи пояснено, хто переміг.

Останній пункт найцінніший. Побачити результат може кожен, назвати причину — ні.

Наступного уроку — розміри: ширина, висота, розмір тексту й одиниці виміру.

Якщо щось не виходить

  • Клас не спрацьовує — перевірте крапку в CSS і точний збіг імені, разом із великими й маленькими літерами.
  • Написали правило, а колір не той — десь є друге правило з більшою вагою. Порахуйте id, класи й теги в обох селекторах.
  • Ваги однакові, а результат дивний — перемагає нижнє правило. Подивіться, що написано далі у файлі.
  • Вкладений чи дочірній селектор не спрацював — відкрийте інспектор і перевірте, чи елемент справді лежить усередині і на якому рівні.
  • h1 + p не спрацював — між ними, мабуть, є ще якийсь тег. Сусід має стояти одразу після.
  • Перевірте пробіл: .card.large і .card .large, a[target] і a [target] — різні правила.
  • Застрягли більше ніж на п'ятнадцять хвилин — пишіть у Classroom або на пошту.
